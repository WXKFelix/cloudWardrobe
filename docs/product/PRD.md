# 《量化人生》产品需求文档（MVP）

**版本**：0.1  
**状态**：MVP 范围锁定  
**最后更新**：2026-09-23

---

## 1. 产品愿景

帮助用户用**可观测的数据**看清人生轨迹，在**关键岔路口**做出更清醒、更少后悔的选择，让人生**有的放矢**，而不是为数字而活。

**一句话定位**：看清你走的线，算清岔口的代价。

**英文副标**：*Life, measured. Choices, clear.*

---

## 2. 问题与机会

| 用户痛点 | 现有方案不足 | 本产品机会 |
|----------|--------------|------------|
| 日常忙碌，不知道时间/精力是否花在主线上 | 习惯 App 只盯 streak，不连接人生目标 | **主线 + 对齐度** |
| 重大选择信息杂、怕后悔 | 纯聊天 AI 无持续状态、数字不可靠 | **结构化节点向导 + 规则计算** |
| 量化工具制造焦虑 | 单一 KPI、人生总分 | **指标可关闭、展示 trade-off** |

---

## 3. 目标用户（MVP）

- **主画像**：22–35 岁，面临或刚经历职业/城市类选择的职场人。
- **首发节点**：是否接受新工作 Offer / 是否换工作。
- **排除（MVP 不做）**：医疗诊断、法律意见、具体投资建议。

---

## 4. 产品原则（宪法）

1. **不做「人生总分」、不做用户排名。**
2. **任何日常指标可降权或关闭**；系统可提示「该指标是否仍在服务你的价值观」。
3. **重大决策输出必须为 2～3 条路径 + 明确 trade-off**，禁止单线「你应该」。
4. **数值由客户端规则引擎计算**；若接入 LLM，仅负责解释与追问，不编造财务/时间数字。
5. **保留「不可量化」输入**：每个重大决策至少一步叙述或「最不想失去的 3 样」。

---

## 5. 核心概念模型

### 5.1 人生隐喻：A → B → C

- **A**：出生/成长锚点（初始条件摘要，用户自愿填写，系统不评判）。
- **B、C、D…**：人生阶段（求学、工作、城市、关系里程碑等），含可选地点与叙事。
- **轨迹**：阶段序列 + 各阶段状态快照；**空间方差小 ≠ 人生空白**（产品文案与指标均需避免偏见）。

### 5.2 状态（State）与对齐（Alignment）

- **六维轻量状态**（MVP）：时间、健康、财务、成长、社交、情绪（0–10 自评，每日 ≤1 分钟）。
- **人生主线**：用户设定 1–3 条（MVP 实现 1 条）。
- **对齐度**：近期签到与「主线投入」自评的综合趋势（非单一公式排名，而是帮助用户看见偏离）。

### 5.3 关键节点（Decision Event）

- 用户主动发起 → 多步向导 → 事实采集 → 情景计算 → 路径对比 → 假设清单 → **复盘日期**。

### 5.4 「最优解」定义（对外话术）

> 在你当前状态与声明的价值观下，**较优的 2～3 条路径**（各有利弊），并标明不确定性与**可逆性**——不是唯一标准答案。

## 6. MVP 功能范围

### 6.1 In Scope

| 模块 | 功能 | 验收标准 |
|------|------|----------|
| Onboarding | 价值观倾向（3 题）、设定 1 条主线、标记当前阶段名与可选「锚点 A」 | 完成后进入主界面，数据本地持久化 |
| 今日 | 30 秒签到（六维简化为 3 项 MVP：精力、主线投入、情绪）+ 对齐度卡片 | 可查看 7 日 sparkline |
| 轨迹 | 垂直时间线：阶段列表，增删改阶段（名称、起止、短叙述） | 至少展示 onboarding 当前阶段 |
| 决策 | 「换工作 / Offer」向导：薪资、通勤、成长、风险、不可量化项 | 输出 ≥2 条路径对比表 + 假设 + 复盘日 |
| 决策日志 | 历史决策列表，查看详情与复盘状态 | 本地 SQLite 存储 |
| 设置 | 编辑主线、导出 JSON 备份（MVP）、产品原则说明 | 导出文件可分享/保存 |

### 6.2 Out of Scope（MVP）

- 账号登录、云端同步、推送通知
- HealthKit / 微信运动 / 自动记账
- LLM 对话（预留 API 文档位）
- 地图可视化、多节点类型（除 Offer 外）
- 微信小程序

## 7. 用户故事（优先级）

1. **P0** 作为新用户，我希望 3 分钟内完成价值观与主线设置，以便 App 知道如何衡量「对齐」。
2. **P0** 作为用户，我希望每天花 30 秒记录状态，以便看见近期是否偏离主线。
3. **P0** 作为用户，我在考虑新 Offer 时，希望输入关键数字后看到多条路径及代价，以便减少后悔。
4. **P1** 作为用户，我希望在时间线上记录经过的人生阶段，以便对照 A→B→C 轨迹。
5. **P1** 作为用户，我希望在复盘日看到当时做的假设，以便修正人生模型。

---

## 8. 关键节点：换工作 / Offer（MVP 详规）

### 8.1 输入字段

| 字段 | 类型 | 用途 |
|------|------|------|
| 当前年薪（税前） |  number | 基准 |
| Offer 年薪（税前） | number | 对比 |
| 单程通勤（分钟） | number | 时间成本 |
| 每周预期加班（小时） | number | 精力成本 |
| 成长空间（1–10） | number | 主观 |
| 风险承受（1–10） | number | 权重 |
| 家庭/稳定约束（1–10） | number | 权重 |
| 最不想失去的 3 样 | text[] | 不可量化 |
| 自由叙述 | text | 不可量化 |

### 8.2 输出

- **路径 A**：接受 Offer（含 1 年净收益粗算、时间成本分、综合标签）
- **路径 B**：留任现职（含机会成本说明）
- **路径 C（条件）**：谈判/延期决策（当薪资增幅边际或通勤恶化时推荐）
- **假设清单**：3–5 条 IF-THEN
- **建议复盘日**：默认 +30 天

### 8.3 计算原则

- 净收益粗算：`(offer - current) * 0.75`（简化的税后因子，可在设置中说明）
- 通勤成本：`(commute_min * 2 * 250 / 60) * 隐含时薪`（MVP 用时薪 = current/2000）
- 综合分：加权，权重随「风险/稳定」调节；**始终展示分项，不单显示一个Winner**

## 9. 成功指标（MVP 验证）

| 指标 | 目标（内测） |
|------|----------------|
| 完成 Onboarding 比例 | > 70% |
| 7 日内 ≥3 次签到 | > 40% 注册用户 |
| 完成 Offer 向导比例 | > 50% 进入向导的用户 |
| 复盘标记完成 | > 30% 到期决策 |

---

## 10. 合规与文案

- 决策结果页固定免责声明：**本应用提供思考框架与粗算，不构成职业、财务或法律建议。**
- 隐私：MVP 数据仅存本机；导出由用户主动触发。
