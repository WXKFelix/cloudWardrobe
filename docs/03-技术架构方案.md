## 三、技术栈明细

### 3.1 前端 — cloud-wardrobe-ui

| 类别 | 技术 | 版本建议 |
|------|------|----------|
| 框架 | Expo (React Native) | SDK 52+ |
| 语言 | TypeScript | 5.x |
| 导航 | Expo Router | v4 |
| 状态管理 | Zustand | 轻量，适合 MVP |
| 网络请求 | TanStack Query + Axios | 缓存 + 请求管理 |
| UI 组件 | NativeWind (Tailwind) | 快速出 UI |
| 相机/相册 | expo-camera, expo-image-picker | 已配置 |
| 图表 | react-native-chart-kit | 穿搭统计 |
| 本地存储 | expo-secure-store + AsyncStorage | Token + 离线缓存 |

### 3.2 后端 — CloudWardrobe

| 类别 | 技术 | 说明 |
|------|------|------|
| 运行时 | Node.js 20 LTS | — |
| 框架 | NestJS | 模块化、TypeScript 原生 |
| ORM | Prisma | 类型安全、迁移管理 |
| 认证 | JWT + Refresh Token | 无状态鉴权 |
| 密码 | bcrypt | 不可逆哈希 |
| 文件上传 | Multer → OSS | 图片直传 |
| 任务队列 | Bull (Redis) | 异步图片处理、推荐生成 |
| API 文档 | Swagger (OpenAPI) | 自动生成 |
| 日志 | Winston + ELK | 结构化日志 |

### 3.3 数据存储

| 存储 | 用途 | 选型 |
|------|------|------|
| 关系数据库 | 用户、衣物、穿搭、订单 | PostgreSQL 16 |
| 缓存 | Session、热数据、限流 | Redis 7 |
| 对象存储 | 衣物照片、捐赠证书 PDF | 阿里云 OSS |
| 搜索 | 衣物模糊搜索 | PostgreSQL pg_trgm（MVP）→ Elasticsearch（V2） |

### 3.4 推荐引擎

| 阶段 | 方案 |
|------|------|
| MVP | 规则引擎：温度区间 → 衣物厚度；场合 → 风格标签匹配 |
| V1.0 | 规则 + LLM（GPT-4o-mini）：将衣橱 JSON + 天气 + 场合发给 LLM 生成搭配 |
| V2.0 | 协同过滤 + LLM：基于穿搭历史学习偏好 |

## 四、核心数据模型

```
User（用户）
├── id, username, password_hash, email, phone
├── user_type: student | worker | family
├── cloud_quota: 50 (默认)
├── created_at, updated_at
│
├── ClothingItem（衣物）[]
│   ├── id, user_id, name, category, color, season
│   ├── brand, purchase_date, price, image_url
│   ├── status: normal | washing | repair | donate | in_storage | wearing
│   ├── tags[], wear_count, last_worn_at
│   ├── unique_label_id (O2O 标签)
│   └── created_at, updated_at
│
├── OutfitRecord（穿搭记录）[]
│   ├── id, user_id, date
│   ├── clothing_item_ids[]
│   ├── occasion, weather_snapshot, notes
│   └── created_at
│
├── StorageOrder（仓储订单，V2）
│   ├── id, user_id, type: inbound | outbound
│   ├── warehouse_id, clothing_item_ids[]
│   ├── delivery_method, status, tracking_number
│   └── created_at
│
└── Membership（会员）
    ├── level: free | standard | premium
    ├── points, expires_at
    └── created_at
```

### 衣物状态机

```
normal（正常）
  → washing（待清洗）
  → repair（待维修）
  → donate（待捐赠）
  → in_storage（在库）
  → wearing（穿着中）
  → donated（已捐赠）
  → disposed（已处置）
```

## 六、安全方案

### 6.1 传输安全

- 全站 HTTPS（TLS 1.3）
- API 请求携带 `Authorization: Bearer <JWT>`
- 敏感操作（删除账号、支付）需二次验证

### 6.2 存储安全

| 数据 | 方案 |
|------|------|
| 密码 | bcrypt (cost=12) |
| 手机号 / 地址 | AES-256-GCM 加密存储 |
| 衣物图片 | OSS 私有桶 + 签名 URL（有效期 1h） |
| JWT Secret | 环境变量注入，不入代码库 |

### 6.3 访问控制

```
请求 → API Gateway 限流 (100 req/min/user)
     → JWT 验证
     → RBAC 权限检查
     → 业务逻辑（user_id 隔离）
```

### 6.4 合规

- 隐私政策 + 用户协议（注册时勾选）
- 支持 `/api/v1/user/export` 数据导出
- 支持 `/api/v1/user/delete` 账号注销（30 天冷静期）
- 日志不含用户敏感信息

## 七、离线模式与数据同步

### 7.1 离线策略

| 功能 | 离线支持 |
|------|----------|
| 查看衣橱列表 | ✅ 本地缓存 |
| 拍照录入 | ✅ 存本地队列，联网后上传 |
| 今日推荐 | ⚠️ 使用缓存的上次推荐 |
| 穿搭打卡 | ✅ 本地记录，联网后同步 |
| 搜索 | ✅ 本地索引 |

### 7.2 同步机制

```
本地操作 → 写入 LocalQueue (AsyncStorage)
         → 网络恢复时 BulkSync
         → 服务端返回冲突列表
         → 客户端按「最新时间戳优先」自动合并
         → 不可合并的冲突提示用户手动选择
```

### 7.3 图片处理流程

```
拍照 → 本地压缩 (max 500KB) → 上传 OSS → 返回 URL → 创建衣物记录
                                    ↓ 异步
                              AI 图像分析 → 更新类别/颜色
```

## 八、部署架构

### 8.1 MVP 阶段（单机）

```
云服务器 1 台 (2C4G)
├── Docker Compose
│   ├── NestJS App (×1)
│   ├── PostgreSQL
│   └── Redis
├── Nginx (反向代理 + SSL)
└── OSS (图片存储，按量付费)
```

### 8.2 成长期

```
                    ┌─ App Server ×2 (负载均衡)
CDN → Nginx LB ────┤
                    └─ Worker ×1 (异步任务)
                         │
                    PostgreSQL (主从)
                    Redis Cluster
                    OSS
```

### 8.3 CI/CD

```
Git Push → GitHub Actions
  ├── 前端：EAS Build → TestFlight / 内测分发
  ├── 后端：Docker Build → 推送镜像 → 自动部署
  └── 数据库：Prisma Migrate
```
