**版本**：v1.0  
**状态**：草案  
**后端项目**：CloudWardrobe  
**前端项目**：cloud-wardrobe-ui

## 一、设计初衷与目标

### 1.1 产品愿景

让穿衣像吃饭一样随性——不再刻板、不再纠结。新世纪的穿衣方式，应该是**随想随穿、随穿随换**。

### 1.2 解决的痛点

| 痛点 | 具体表现 |
|------|----------|
| 衣物堆成山 | 家里衣柜爆满，换季整理痛苦，大量衣物闲置 |
| 出门穿搭焦虑 | 每天站在衣柜前不知道穿什么 |
| 出行行李沉重 | 出差/旅游需反复纠结带哪些衣服，行李箱被占满 |
| 衣物生命周期混乱 | 旧衣不知如何处理，缺少捐赠/置换渠道 |
| 保养缺失 | 皮衣、羊绒等高档衣物缺乏定期护理提醒 |
| 物理风险 | 火灾等意外导致衣物损毁，缺乏备份与异地保障 |

### 1.3 满足的需求

1. **随时想换就换、想穿就穿**——数字衣橱 + 智能推荐
2. **异地取还**——外出旅游不必把整柜衣服塞进行李箱
3. **每天穿不同类型**——轮换穿搭，提升衣物利用率
4. **旧衣捐赠 / 折旧置换**——闭环处理闲置衣物
5. **时尚穿搭提醒**——天气、场合、个人风格综合推荐
6. **衣物保护与定期护理**——保养周期提醒 + 门店护理服务

### 1.4 核心目标用户

| 用户群 | 典型画像 | 核心诉求 | 产品策略 |
|--------|----------|----------|----------|
| **学生党** | 18–25 岁，宿舍空间有限，预算有限 | 低成本换装、社交穿搭、空间节省 | 免费云空间、轻量录入、穿搭分享、二手/捐赠 |
| **上班族** | 25–40 岁，通勤穿搭、商务出差频繁 | 高效决策、出差异地取衣、形象管理 | 每日推荐、出差模式、门店快捷换衣 |
| **家庭用户** | 有孩家庭、多成员共用空间 | 四季衣物管理、儿童衣物轮换、全家衣橱 | 家庭成员分组、子账号、批量收纳服务 |

### 1.5 用户主要问题

- **决策成本**：「今天穿什么」消耗大量时间
- **空间成本**：居住面积小，衣物物理存储压力大
- **移动成本**：跨城/跨国出行携带衣物不便
- **管理成本**：不记得有什么、放在哪、多久没穿
- **处置成本**：旧衣捐赠/回收渠道不清晰

### 1.6 竞品与差异化

#### 市场现有方案

| 类型 | 代表产品 | 能力边界 |
|------|----------|----------|
| 数字衣橱 App | Stylebook、Acloset、衣橱记 | 仅数字化管理，无实体服务 |
| 衣物租赁 | 衣二三（已停运）、星宿 | 租衣服，非「自己的衣服」 |
| 迷你仓储 | 迷你仓、考拉仓 | 纯物理存储，无穿搭智能 |
| 穿搭社区 | 小红书、得物 | 内容种草，非个人衣橱管理 |
| 电商搭配 | 淘宝搭配购 | 导购导向，非衣橱 OS |

#### 云衣柜差异化定位

```
数字衣橱（管理） + 智能穿搭（决策） + 实体仓储（物流） + 门店体验（O2O）
```

| 差异点 | 说明 |
|--------|------|
| **自有衣物上云** | 不是租，是用户自己的衣服，数字化后可管理、可流转 |
| **唯一标签体系** | 每件衣物入库即打 RFID/二维码标签，全链路可追溯 |
| **异地取还** | 跨省/跨国仓储网络，出差旅游轻装出行 |
| **门店换衣体验** | 旧衣送洗整理，用户直接穿新衣出门店 |
| **灾难安全备份** | 云端数字档案 + 实体仓库存储，双重保障 |
| **全生命周期** | 购买 → 穿着 → 保养 → 捐赠/折旧置换，一站式 |

## 二、核心功能

### 2.1 核心功能矩阵

| 功能 | 解决什么问题 | 用户价值 |
|------|-------------|----------|
| **衣物录入** | 衣物信息分散、记不住 | 拍照/手动录入，一键上云，建立数字档案 |
| **分类整理** | 找不到、理不清 | 按季节/类型/颜色/场合多维分类与标签 |
| **智能搭配** | 穿搭决策困难 | 结合天气、场合、偏好，每日推荐穿搭方案 |
| **穿搭记录** | 重复穿搭、无法回顾 | 记录每日穿着，统计使用率，发现闲置 |
| **时尚资讯** | 缺乏穿搭灵感 | 推送趋势、场合指南（轻量，非社区重运营） |

### 2.2 O2O 增值服务（差异化核心）

| 功能 | 说明 |
|------|------|
| **唯一标签** | 平台存储的衣物自动分配唯一 ID（RFID/二维码），支持全程追踪 |
| **异地存取** | 衣物存入 A 城仓库，B 城门店/快递取还 |
| **门店换衣** | 用户到门店，旧衣交洗，换已整理好的衣物直接出门 |
| **定期保养** | 系统提醒 + 门店护理服务（干洗、熨烫、除菌） |
| **自取 / 配送** | 灵活选择到店自取或快递配送 |

### 2.3 次级功能（增值但不冗余）

| 功能 | 价值 | 冗余控制原则 |
|------|------|-------------|
| 捐赠通道 | 旧衣处置闭环 | 对接机构 API，不做自建慈善体系 |
| 折旧置换 | 变现闲置 | 引导至合作回收商，不做自营二手交易（初期） |
| 会员积分 | 留存激励 | 与云空间、取衣次数、保养折扣挂钩 |
| 数据报表 | 穿搭分析 | 嵌入仪表盘，不单独做复杂 BI |
| 微信登录 | 降低注册门槛 | V1.5 接入，MVP 用账号密码 |

**不做的（至少 MVP 阶段）**：即时通讯、完整电商、AR 试穿、站内社区——与核心价值链无关，投入产出比低。

### 2.4 功能优先级

#### P0 — 必须（MVP）

- 账号注册 / 登录
- 新用户赠送云空间
- 衣物拍照录入 + 手动信息补充
- 分类 / 标签 / 搜索
- 今日穿搭推荐（天气 + 规则引擎）
- 穿搭打卡记录
- 首页仪表盘（衣橱概览）

#### P1 — 重要（V1.0）

- 智能搭配优化（LLM 辅助）
- 清洗 / 保养提醒
- 捐赠 / 折旧申请流程
- 云同步 + 多设备
- 时尚资讯 Feed（精选内容）
- 个人中心 / 会员基础框架

#### P2 — 增值（V2.0 · O2O）

- 衣物唯一标签体系
- 仓储入库 / 出库流程
- 异地取还预约
- 门店换衣服务
- 自取 / 配送物流跟踪
- 微信登录

#### P3 — 扩展（V3.0+）

- 跨省 / 跨国仓储网络
- 门店合作 SaaS
- 品牌扫码购即入库
- 积分商城 / 会员等级
- 开放 API 对接

## 三、用户体验设计（UX）

### 3.1 设计原则

1. **3 分钟上手**：首次使用 3 分钟内完成注册 + 录入第一件衣物
2. **先穿后理**：优先展示「今天穿什么」，而非衣橱管理
3. **录入极简**：拍照即入库，详细信息可后补
4. **渐进式引导**：功能按需展开，不一次性展示全部能力
5. **千人千面**：学生 / 上班族 / 家庭用户看到不同默认首页模块

### 3.2 核心用户路径

```
下载 App → 注册（赠云空间）→ 引导录入首件衣物 → 查看今日推荐 → 穿搭打卡 → 日常使用
```

### 3.3 首页信息架构

```
┌─────────────────────────────────┐
│  今日天气 + 穿搭推荐（主卡片）    │
├─────────────────────────────────┤
│  快捷入口：录入 | 衣橱 | 记录    │
├─────────────────────────────────┤
│  衣橱概览（数量 / 类别饼图）      │
├─────────────────────────────────┤
│  提醒：待清洗 | 待保养 | 换季      │
├─────────────────────────────────┤
│  时尚灵感（1-3 条精选）          │
└─────────────────────────────────┘
```

### 3.4 降低学习曲线

| 手段 | 说明 |
|------|------|
| 新手引导 | 3 步引导：录入 → 推荐 → 打卡 |
| 空状态设计 | 无衣物时展示示例穿搭卡片 + 「拍第一件」CTA |
| 上下文帮助 | 每个页面右上角「?」浮层，不超过 3 句话 |
| 智能默认值 | 录入时 AI 预填类别/颜色，用户只需确认 |
| 操作反馈 | 录入成功绿勾动画、推荐生成进度条 |

### 3.5 个性化体验

- **用户类型选择**：注册后选择学生 / 上班族 / 家庭，影响推荐权重与首页布局
- **风格偏好**：休闲 / 商务 / 运动 / 混搭，影响搭配算法
- **穿衣频率**：高频用户推每日推荐；低频用户推换季整理提醒
- **主题定制**：明暗模式（V1.0）

## 五、数据安全与隐私保护

### 5.1 数据分类

| 数据类型 | 敏感级别 | 存储策略 |
|----------|----------|----------|
| 账号凭证 | 高 | bcrypt 哈希 + JWT，密码不可逆 |
| 衣物照片 | 中 | OSS 私有桶 + 签名 URL 访问 |
| 穿搭记录 | 中 | 数据库加密字段，用户可导出/删除 |
| 地址 / 手机号 | 高 | AES-256 加密存储，展示脱敏 |
| 行为日志 | 低 | 匿名化，90 天滚动删除 |

### 5.2 合规要求

- 中国：《个人信息保护法》《数据安全法》
- 海外扩展：GDPR（欧盟）、CCPA（加州）
- 隐私政策 + 用户协议，注册时明示同意
- 支持账号注销与数据完全删除

### 5.3 权限管理

- 用户仅可访问自己的衣橱数据
- 家庭账号支持「只读 / 可编辑」子权限
- 后台管理 RBAC 权限体系
- API 全链路 HTTPS + 请求签名

## 八、成本与收益模型

### 8.1 成本结构

| 成本项 | MVP 阶段 | 成长期 |
|--------|----------|--------|
| 研发 | 2–3 人 × 3 个月 | 5–8 人团队 |
| 云服务 | ¥500–2000/月 | 按用户量线性增长 |
| AI API | ¥0.01–0.05/次推荐 | 可切换自部署模型降本 |
| 仓储物流 | 无（纯数字） | 单城试点 ¥5–10 万/月 |
| 运营推广 | ¥1–3 万/月 | 按渠道 ROI 投放 |

### 8.2 收益模型

| 模式 | 说明 | 与体验关系 |
|------|------|-----------|
| **订阅会员** | 月费 ¥15–49，扩容云空间 + 高级推荐 | 不冲突，免费版可用核心功能 |
| **取衣 / 保养服务费** | 单次 ¥10–50（物流 + 洗护） | 按需付费，不强制 |
| **导购分成** | 推荐购买链接 CPS 分成 | 轻量展示，不弹广告 |
| **门店合作 SaaS** | 向服装门店收取数字化服务费 | B 端收入，不影响 C 端 |

### 8.3 平衡原则

- **免费版必须能完成核心闭环**：录入 → 推荐 → 记录
- 付费点放在「扩容」和「物理服务」，而非基础功能阉割
- 时尚资讯不做信息流广告，保持体验纯净
